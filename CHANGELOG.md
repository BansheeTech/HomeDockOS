# CHANGELOG

- **2.6.2.104** (Latest): Fixes blank HTTPS windows, stuck port scans, blank sub-subdomains OnScreen Apps, Start Menu iOS longress hotfix and updated dependencies.
  - **Sonarr, Radarr and friends no longer go blank over HTTPS.** When their session expired, they redirected to their login page with a hardcoded `http://` address, ignoring `X-Forwarded-Proto`, and the browser refused to load it inside the HTTPS app window, leaving it empty with a Content Security Policy error. The built-in reverse proxy now upgrades those redirects to `https://` when they point back at the app itself. Redirects anywhere else are left untouched, and over plain HTTP, `homedock.localhost` included, nothing changes.
  - **New apps no longer get stuck scanning for their port.** The task that finds each app's web port gave up for good the first time Docker took more than 60 seconds to answer, something a busy Raspberry Pi pulling an image can easily do. From then on every new app, and every Rescan ports, stayed on the scanning animation until HomeDock OS was restarted. It now skips that round and tries again 10 seconds later.
  - **App subdomains are for apps only.** DuckDNS, freemyip and `*.homedock.localhost` resolve any subdomain to your machine, so `anything.yourname.duckdns.org`, or the address of an app you had uninstalled, opened the HomeDock OS login. Subdomains of your HomeDock OS address that don't belong to an app now answer "No app at this address." The desktop stays at the address you configured, and your apps at theirs.
  - **Long-pressing an app in the Start menu on iPhone opens its menu again.** The press landed on the app's icon image, so iOS showed its own image preview instead of the app menu. Start menu icons now behave like the ones on the desktop, which never had this problem.
  - **App icons look the same in Safari as everywhere else.** Safari mistook nearly square PNG icons, like Hermes, for transparent ones and shrank them, and opaque icons are now zoomed 3% so thin frames baked into some community icons don't show on high-density screens.
  - **Patched Vue `GHSA-g2v6-rqmx-r4w6`** by upgrading `vue` (npm) from 3.5.35 to 3.5.43 in `package.json`. `@vue/server-renderer` let an attribute name carrying a carriage return slip past its blacklist, an XSS when rendering on the server. HomeDock OS renders everything in the browser and never calls the server renderer, which `vue` simply ships alongside, so it was never reachable.
  - **Writer got a better engine** by upgrading `@docx-editor.dev/core` and `@docx-editor.dev/vue` (npm) from 2.23.0 to 2.27.0. Tables that size their columns to their content come out right, long tables continue onto the next page instead of hiding their last rows, text flows beside floating tables instead of being pushed below them, optional hyphens break words at the end of a line, text boxes can be inserted and edited, old Word text boxes and shapes show up, equations render, and documents in reading mode no longer show a caret. Undo now takes back one run of typing at a time instead of whole paragraphs, and pasting requires the `prosemirror-view` release that fixes `GHSA-c8x8-7fp4-3x9w`.
  - **PDF.js 6** by upgrading `pdfjs-dist` (npm) from 5.5.207 to 6.4.299. The PDF Viewer now closes documents through their loading task, since 6.0 removed `PDFDocumentProxy.destroy()`. PDF.js 6 needs Chrome 125 or Safari 18 (both from 2024) or later, so the PDF Viewer no longer opens on older browsers.
  - **zip.js 2.23** by upgrading `@zip.js/zip.js` (npm) from 2.18.2 to 2.23.0, for the ZIP files you drop on Archives from your computer. A Unicode Path extra field could swap an entry's validated name for an unsafe one such as `../evil.txt` after the check had run; the check now covers the final name. Damaged archives whose entries point outside the file are rejected instead of being read halfway.
  - **The rest of the interface dependencies moved forward** (npm, `package.json`): `@codemirror/language` 6.12.4 → 6.13.1, `@codemirror/view` 6.43.13 → 6.43.14, `@iconify-icons/mdi` 1.2.48 → 2.0.0, `@iconify/vue` 5.0.1 → 5.0.3, `@noble/ed25519` 3.1.0 → 3.2.0, `@noble/hashes` 2.3.0 → 2.4.0, `@tanstack/vue-virtual` 3.13.35 → 3.13.39, `@unhead/vue` 2.1.17 → 3.4.2, `dayjs` 1.11.21 → 1.11.23, `highlight.js` 11.11.1 → 11.12.0, `marked` 18.0.9 → 18.1.0, `music-metadata` 11.14.0 → 12.0.0, `pinia` 3.0.4 → 4.0.3, `vue-i18n` 11.4.8 → 11.4.13 and `vue-router` 4.6.4 → 5.4.0. No code changes needed: every icon we use exists in the new icon set and looks the same, Enterprise module signatures still verify over plain HTTP, and the favicon, stores, routes and translations behave as before.
  - **The build tools moved forward too** (npm, `package.json`): `vite` 8.2.1 → 8.3.3, `@vitejs/plugin-vue` 6.0.8 → 6.0.9, `@vitejs/plugin-react` 6.1.1 → 6.1.2, `esbuild` 0.28.1 → 0.28.2, `postcss` 8.5.26 → 8.5.29 (override included), `vue-tsc` 3.3.9 → 3.3.12 and `@types/node` 25.6.0 → 26.6.4. `@types/dompurify` is gone, as DOMPurify ships its own types.
  - **Kept `typescript` at 6.0.3.** TypeScript 7 is the native Go compiler and no longer ships the JavaScript API that `vue-tsc` builds on, so type checking `.vue` files would stop working altogether. The Vue team plans to support it through TypeScript 7.1's content mappers; we will move once that lands.
  - **Moved to Tailwind CSS 4** by upgrading `tailwindcss` (npm) from 3.4.19 to 4.3.3, built through `@tailwindcss/postcss`. `autoprefixer` and `tailwind.config.js` are gone, and the whole setup now lives in `global.css`. The build-time advisories against Tailwind 3's dependencies (`braces`, `postcss-selector-parser`) go away with it, leaving `node-forge` as the only entry in `npm audit`. Tailwind's utilities are kept outside CSS cascade layers on purpose. Inside a layer they lose to ant-design's own styles, and inputs, buttons and selects in Noir and Aero would fall back to its light defaults. A handful of renamed or rescaled classes (`outline-none`, `shadow-sm`, `backdrop-blur-sm`, `rounded-sm`, gradients) were migrated by hand. Classes that never worked under Tailwind 3 were removed rather than suddenly coming to life, and Enterprise modules compile their CSS with the same setup. Tailwind 4 needs Safari and iOS 16.4, Chrome 111 or Firefox 128 or later.
  - **The server dependencies moved forward** (pip, `requirements.txt`): `Flask-Compress` 1.23 → 1.25, `docker` 7.1.0 → 7.2.0, `requests` 2.33.0 → 2.34.2, `Werkzeug` 3.1.6 → 3.1.9, `psutil` 7.1.3 → 7.2.2, `zeroconf` 0.150.0 → 0.151.5, `pyotp` 2.9.0 → 2.10.0, `aiohttp` 3.14.3 → 3.14.4 and `cython` 3.2.0 → 3.3.0. Werkzeug 3.1.9 closes `GHSA-g6x2-hccm-hh4m`, where `safe_join` accepted Windows device names with an empty NTFS stream marker. psutil now publishes wheels for Alpine, so the Docker image no longer compiles it. docker 7.2.0 follows your active Docker context when `DOCKER_HOST` is not set, the same way the `docker` CLI already did. Every one of them installs from ready-made wheels on Windows, macOS and Linux, wherever the previous versions did.
  - **Kept `Hypercorn` at 0.17.3.** 0.18.0 sends a response's headers together with its first chunk of body, so a response with no body never sends them at all: every `304 Not Modified`, `HEAD` and `204` from HomeDock OS turns into a 500, and browser caching dies with it. It is reported upstream as [pgjones/hypercorn#331](https://github.com/pgjones/hypercorn/issues/331) and still open.
  - **Kept `cryptography` at 48.0.1**, the last 48.x. From 49.0 it only publishes macOS wheels for Apple Silicon, so installing it on an Intel Mac would mean building it from source with a Rust toolchain. 50.0 also fixes **CVE-2026-69247**, a Bleichenbacher oracle in PKCS#7 decryption, which HomeDock OS never uses.
    > **TL;DR:** Thirty-odd packages newer, one line of code changed for PDF.js, and three kept back on purpose: Hypercorn because it breaks caching, cryptography because it leaves Intel Macs behind, and TypeScript because it would stop checking our `.vue` files. Upgrades should never be the thing that breaks your box, selfhosters!

- **2.6.2.102**: Last time fixes for urllib3, axios, DOMPurify and uuid security dependency upgrades, closing 16 CVEs and 1 GHSA advisory, plus a fix for Enterprise modules.
  - **Patched 3 urllib3 CVEs** by upgrading `urllib3` (pip) from 2.7.0 to 2.8.0 in `requirements.txt`. HomeDock OS streams mostly from the local Docker socket, a source it already trusts, so exposure was low, but a minor bump was not worth arguing about.
  - **CVE-2026-97689** — `HTTPResponse.stream()` / `read_chunked()` buffered an unbounded chunk-size line into memory, letting a malicious server send an endless run of bytes with no newline and exhaust the client's memory before urllib3 could reject it. 2.8.0 rejects chunk-size fields over 65536 bytes, as the non-streaming path already did.
  - **CVE-2026-97687** — HTTPS proxy TLS configuration could be ignored or overridden by the target's: `proxy_ssl_context` skipped in forwarding mode, `cert_reqs="CERT_NONE"` for a target silently disabling verification of the proxy (in place, so it persisted on reused contexts), and target SNI, fingerprints or client certificates presented to the proxy.
  - **CVE-2026-97688** — Chunked Deflate streaming could enter an infinite loop when bytes followed the end of the Deflate stream, spinning the CPU forever with no socket read for a timeout to interrupt.
  - **Patched 12 axios CVEs** by upgrading `axios` (npm) from 1.18.0 to 1.20.0 in `package.json` (and re-resolving `package-lock.json`). axios only runs in the browser in HomeDock OS, so every Node-adapter path below was out of reach, and the prototype-pollution gadgets all need a pollution source somewhere else in the same process first. Closed anyway, because they always come back in pairs.
  - **CVE-2026-101909** — Prototype-pollution gadget in `toFormData()`: `visitor`, `maxDepth`, `dots`, `indexes`, `metaTokens` and `Blob` were read without own-property guards, so a polluted `Object.prototype` could rewrite field names or make every nested form submission throw.
  - **CVE-2026-101906** — Quadratic ReDoS in `shouldBypassProxy()` hostname normalization (`/\.+$/`), reachable through a crafted redirect `Location` whenever `NO_PROXY` is set.
  - **CVE-2026-101901** — Unhandled `error` event on the HTTP/2 `ClientHttp2Session` crashed the whole Node.js process instead of rejecting the request.
  - **CVE-2026-101903** — ReDoS in the `fromDataURI` `data:` URL parser, freezing the event loop on a malformed URL full of slashes before any timeout could kick in.
  - **CVE-2026-101905** — Inherited `createConnection` in the Node HTTP adapter let a polluted prototype redirect the request socket to an attacker endpoint, `Authorization` header included, while the URL still looked legitimate.
  - **CVE-2026-101898** — The HTTP/2 adapter bypassed the configured DNS `lookup` and proxy controls, opening an SSRF path for apps that rely on them as policy.
  - **CVE-2026-101900** — Fetch adapter header injection through an inherited `FormData` `getHeaders`, a guard the Node adapter already had and `resolveConfig()` did not.
  - **CVE-2026-101907** — `maxRedirects: 0` was not enforced by the fetch adapter, which happily followed redirects anyway, allowing redirect-based SSRF.
  - **CVE-2026-101904** — Header injection through an inherited `headers` when a request interceptor returns a rebuilt config without its own `headers`. Our only interceptor is a response one, so this never applied.
  - **CVE-2026-101908** — The fetch adapter passed the original `fetchOptions` to `fetch()` instead of the resolved ones, so inherited `headers` could override and drop the real request headers.
  - **CVE-2026-101902** — Inherited `Object.prototype.method` overrode the HTTP method on the default instance, turning a `GET` into a `DELETE`.
  - **CVE-2026-101899** — CIDR-form `NO_PROXY` entries (`10.0.0.0/8`, `169.254.169.254/32`) were ignored, sending traffic meant to stay internal through the proxy.
  - **Patched DOMPurify `GHSA-p98j-92pf-mc4p`** by raising `dompurify` from `^3.4.1` (3.4.13 resolved) to `^3.4.16`. In `IN_PLACE` mode, a node removed from an `afterSanitizeElements` or `afterSanitizeAttributes` hook left its descendants' `on*` handlers armed, a DOM XSS. The Notepad's Markdown preview does replace nodes from an `afterSanitizeAttributes` hook, which is exactly the pattern the advisory describes, but it sanitizes strings rather than live DOM, so `IN_PLACE` never comes into play. Low severity, no CVE associated.
  - **Patched uuid CVE-2026-41907** by adding a `uuid` `^11.1.1` override in `package.json`, moving the copy pulled in by `@fortune-sheet/core` and `exceljs` (via `@corbe30/fortune-excel`) from 8.3.2 to 11.1.1. `v3()`, `v5()` and `v6()` skipped the output-buffer bounds check that `v1()`, `v4()` and `v7()` perform, silently writing partial UUIDs. Both dependencies only ever call `v1()` and `v4()`, so it was never reachable; the override just closes the alert.
  - **Kept `node-forge` at 1.4.0** despite **CVE-2026-85393** (`GHSA-86w9-cpqp-85rv`), an incomplete fix for CVE-2026-33894 where RSA PKCS#1 v1.5 signature verification accepts garbage inside nested `DigestAlgorithm` sequences, allowing forged signatures with low-exponent keys. There is no patched release yet, and HomeDock OS is not affected: node-forge is a direct dependency only, nothing else in the tree requires it, and it is used solely for random bytes, RSA-OAEP / AES-GCM encryption of credentials towards the server, SHA-256 and Base64. `publicKey.verify()`, the only entry point to the vulnerable `DigestInfo` parsing, is never called. We will upgrade as soon as a fixed release ships.
  - **Enterprise modules with a status bar compile again.** Since the status bar started showing each window's own app icon, it reaches into the window store and, through it, the registry of every app in HomeDock OS. Enterprise modules are built as a single self-contained script, so Carrier, DataSpace, Firewall, LocalGPT and Prospector tried to swallow the entire OS, Writer included, and Writer's editor uses a top-level `await` that a single-script build cannot express. The host now publishes the window store and the app registry to Enterprise modules the same way it already shares Vue and Prism, one copy per page, so modules use HomeDock OS's own instead of carrying a copy. Back to their usual size, with the window icon in the status bar like every other app. Modules built this way need HomeDock OS 2.6.2.102 or later; the ones already installed keep working as they are.
    > **TL;DR:** Sixteen CVEs and one advisory, and the honest count of the ones that could actually touch HomeDock OS is close to zero: Node-only axios paths in a browser bundle, a DOMPurify mode we never enable, uuid functions nobody calls and a node-forge function we never use. Patched everything that had a patch anyway, because "not reachable today" has a way of aging badly. Keep your dependencies fresh, selfhosters!

- **2.6.2.88**: Introducing the **Container Terminal**, a **Task Manager-grade Control Hub**, **live Logs**, **protected App Drive volumes**, **Sheets**, **Writer**, **image thumbnails**, a redesigned **Start menu**, a rebuilt **Finder**, a new **App Store**, a rebuilt **Packager** and our first games, **Neon Rush** and **Packet Snake**.
  - **Every app now has a terminal.** Right-click any application and you get a real shell inside its container, the same one `docker exec -it` would give you on the host, except you never had to SSH into the host to get it. `vi`, `top`, tab completion, arrow-key history, `Ctrl+C`, colors, full-screen programs, the lot. It is not a text box pretending to be a console: it is a console.
  - **It opens from wherever you already are.** The desktop, a folder, the Control Hub, the app's own window status bar, or any member of a group in Application Properties. And yes, dependencies too: your Postgres finally gets a shell without you having to remember its container name.
  - **It picks the right shell and tells you what it picked.** Bash if the image has it, ash on Alpine, plain sh everywhere else, and a menu to switch between whatever the container actually ships. You can run as the container's own user or as root, and if the image is one of those distroless ones with no shell at all, the window says so instead of hanging there looking thoughtful.
  - **Closing the window actually ends the session.** Docker has a charming habit of leaving your shell, and everything you started from it, running forever after the connection is gone. We checked. It does. HomeDock OS now hangs up the shell the moment the window closes, the tab closes or the connection drops, so `top` does not keep running in a container nobody is looking at.
  - **Colors, without touching a single file in your container.** Most images ship with a prompt that looks like it was designed in 1994 by someone who disliked color. The terminal gives you a readable prompt, red for root and green for everyone else, plus colored `ls` and `grep`, loaded on the fly and gone when you close the window. If your image already has a colorful prompt of its own, we leave it alone. And yes, there is a HomeDock OS logo in the banner. We are a small team from Spain; the logo is our marketing budget.
  - **It behaves like a terminal on your phone too.** A row of extra keys (esc, tab, ctrl, alt, arrows, `|`, `~`, `/`, `-`) sits above the keyboard, because nobody has ever managed to type `Ctrl+C` on a touchscreen and we were not going to be the first to pretend otherwise. Find, copy, paste, clear scrollback and font size live in real menus, and it follows the three themes, frosted Aero included.
  - **The Control Hub grew up into a Task Manager.** Five tabs: **Performance**, **Processes**, **App history**, **Dependencies** and **Details**. Sortable columns with a heat map, apps and background processes split apart, dependencies nested under the app they belong to, `Del` to end a task, `F5` to refresh, right-click or long-press for everything else. If you have ever opened Task Manager on Windows 11, you already know how to use it. We will not tell anyone.
  - **Performance draws live graphs of the whole machine.** CPU, memory, disk, network and temperature, each with its own 60-second graph, plus disk I/O, network I/O and load average, which HomeDock OS had never measured before. You can finally tell whether it is your box that is slow or your patience.
  - **Details gives every container its own card with live CPU and memory graphs.** Uptime, ports, container ID one click from your clipboard, and each dependency listed inside the app it belongs to, so you can see which part of Immich is eating your RAM. Spoiler: it is the machine learning.
  - **Memory is now shown in megabytes, not in percentages that mean different things.** A container capped at 512 MB and one with no cap at all could both read 50% while using wildly different amounts. The Control Hub now shows real memory, which, unlike the percentage, you can compare between two containers without a calculator.
  - **Dependencies stopped being invisible.** If your Nextcloud database is down, the Nextcloud icon on your desktop now tells you with a small badge instead of letting you find out from a blank page. Application Properties warns you, lists every container in the group with quick access to its logs, terminal and properties, and dependency windows carry a little cube so you always know whose database you are looking at.
  - **One row of icons instead of five menu entries.** Right-click an app and **Terminal**, **Logs**, **Control Hub** and **App Drive** sit side by side in a single row, with the same highlight as the rest of the menu. In the Control Hub's own menu the row swaps Control Hub for **Edit Config**, since you are already there.
  - **App Drive now shows volumes outside HomeDock OS, protected like Disks+.** Plex pointing at `/mnt/media`, Jellyfin at an external drive: those folders used to simply not exist as far as App Drive was concerned. Now they show up, locked, and ask for your HomeDock OS password before opening, with its own dialog showing the app's icon and exactly which host folder it is about to open. Protected system paths like `/etc` or `C:\Windows` ask again, Each app unlocks on its own, dependencies included, so opening Immich's volumes doesn't quietly open Jellyfin's too, and a countdown ring on the app tells you how long it has left.
  - **App Drive shows each app's dependencies too.** Your database volumes sit right under the app that owns them, with the same cube badge as everywhere else.
  - **App Drive finally works on Windows.** HomeDock OS writes volumes as `/mnt/c/HomeDock/...` because Docker runs inside WSL2, and App Drive looked for them as `C:\HomeDock\...`. Same folder, two spellings, and they had been politely ignoring each other since day one. They are now on speaking terms, and every app's volumes show up where they always should have.
  - **Logs got rebuilt from scratch.** Out went the gray text box and the auto-refresh switch. Logs are now always live, keep the colors your app prints, and show the time of every line. Errors come tinted red, warnings amber, and the status bar counts the errors for you. Search highlights as you type, a filter leaves only warnings or errors, and you can pick the last 15 minutes, hour or day. Download asks how far back you want to go, the last 15 minutes, hour, day or the whole thing, only offers the ones that actually have something in them, and tells you how big the whole thing is before you commit to it. Immich, we are looking at you and your 25 MB.
  - **Logs let you read in peace.** Scroll up to look at something and the view stays exactly where you left it, while a small "↓ 12 new lines" button waits at the bottom to bring you back. Just like Console on a Mac, minus the 40,000 lines about Bluetooth.
  - **Spreadsheets open in Sheets, and you can actually edit them.** Double-click any `.xlsx` in the File Explorer and it opens in **Sheets**, a real spreadsheet editor living inside HomeDock OS: formulas, several sheets, bold, colors, borders, merged cells, frozen panes, column widths. Change what you need, press `Ctrl+S` and it goes back to the same file, whether it lives in Storage, the Drop Zone, an App Drive volume or a Disks+ drive. No office suite container to install, no uploading your budget to someone else's cloud.
  - **It leaves your files the way it found them.** Formulas keep their results, numbers stay numbers so `SUM` still adds them up when the file goes back to Excel, text that only looks like a number (hello, `00123`) stays text, and dates stay dates. Undo works on everything, column widths included, and closing with unsaved changes asks first.
  - **It weighs nothing until you open a spreadsheet.** Sheets and its engine only download the first time you need them, so the desktop starts exactly as fast as it did before. Your family's shopping list in `.xlsx` finally has a home that is not an email attachment.
  - **Word documents open in Writer, and you can edit those too.** Double-click any `.docx` and it opens in **Writer**, a proper page editor: headings, bold, colors, lists, tables, images, headers and footers, right-to-left text, the works. It saves back to the same file wherever it lives, and what you did not touch comes back exactly as it was. It follows the dark themes, speaks German, Spanish, French, Portuguese and Chinese, and politely switches to English everywhere else until someone translates it.
  - **New documents stay in HomeDock OS.** Start a blank document in Writer or a blank spreadsheet in Sheets, press `Ctrl+S` and it asks for a name and saves it in `Storage/Documents`, not in your browser's Downloads folder. Pick a name that already exists and you get `(1)` added instead of losing the old file. From then on, saving goes straight back to that file.
  - **The File Explorer finally shows you your pictures.** Images in Storage, the Drop Zone, App Drive and Disks+ show a thumbnail of what is inside instead of the same generic icon repeated forty times, so finding the good photo no longer means opening all of them one by one. JPEG, PNG, GIF, WebP, AVIF, TIFF, BMP, icons, Photoshop files and the RAW files from most cameras (Canon, Nikon, Sony, Fujifilm, Panasonic, Pentax, Samsung and DNG), rotated the right way up.
  - **Thumbnails cost almost nothing.** Only the ones on screen are made, a few KB each, and they are remembered, so the second visit to a folder is instant. Edit a photo or overwrite it and its thumbnail follows on its own. In the Drop Zone they are made on the fly and never written to disk: its files are encrypted, and an unencrypted copy of each picture sitting next to them would rather defeat the point.
  - **The Image Viewer opens what your browser can't.** Photoshop files, camera RAW, TIFF, AVIF, TGA, JPEG 2000 and friends now open in the Image Viewer instead of leaving you with a thumbnail you can look at but not open. HomeDock OS converts them on the server and hands the viewer an image it understands, up to 4096 pixels, while the title and status bar still tell you it is a PSD or a NEF. TIFF files in particular had been opening as a broken image in Chrome and Firefox all along, as only Safari can show them; that is over too.
  - **HomeDock OS now comes with a game: Neon Rush.** Every self-respecting operating system ships one, and ours is an endless arcade racer down a synthwave highway: neon road, a striped sunset, traffic to dodge and a boost to burn, driven in a black and white hatchback with its pop-up headlights up that any mountain pass tofu delivery driver would recognise, to a soundtrack of our own. A minimap shows the next kilometre of road so you see the curve coming before it sees you. The boost doesn't refill by itself: you earn it back by grabbing the spinning cubes on the road, which wear the icons of your own installed apps (or the HomeDock OS logo if you have none yet), so yes, you can literally run over your Jellyfin for speed. It gets faster the longer you survive, your best run is saved to your account so it follows you from the PC to your phone, and it lives in its own **Games** section in My Home and the File Explorer, not cluttering the Start menu.
  - **It plays wherever HomeDock OS does.** Arrow keys or WASD on a keyboard, a gamepad if you have one plugged in, and on phones you tap left or right to steer and hold the bolt to boost. It pauses by itself when you switch windows, minimize it or lock your phone, because nobody should lose a record to a notification.
  - **And a second one: Packet Snake.** The classic snake, on a neon grid seen from above, and what it eats are packets wearing the icons of your installed apps, so your Nextcloud finally feeds something. Every ten packets the board grows by a row and a column, up to 30 by 30, and the snake speeds up as it gets longer while its own chiptune soundtrack, generated on the fly, speeds up with it. Now and then a small terminal shows up typing `sudo -s`: grab it before it fades and for eight seconds you are root, which here means going through walls and through yourself while packets rain onto the board.
  - **Same rules as Neon Rush.** Arrow keys or WASD, swipes on a phone, pause when you switch windows or lock the screen, and a best score saved to your account. Leave it on the title screen and the snake plays by itself, just to show off.
  - **Your desktop now follows you, and adapts to wherever it lands.** Folders, what is inside them, your widgets, the system and Enterprise apps you pinned and the icons you removed are now saved to your account instead of your browser, so the folder you made on your home PC is waiting for you on the office one, contents included.
  - **Each device keeps its own layout.** The first device you set up becomes the reference: a new one starts with everything exactly where you put it there, and whatever doesn't fit on its screen moves to the first free spot, in the same order. From then on that layout belongs to that device, so tidying up your laptop never scrambles your 27-inch monitor, and going back to the monitor finds every icon where you left it. Add a widget on your phone and it shows up on the PC too, in a free space, without landing on top of anything.
  - **Your apps stop forgetting where they live after an update.** Updating an app used to send it back to the corner and take it out of its folder, as the desktop remembered it by an ID that changes with every update. It now remembers it by name, which doesn't.
  - **Moving icons on a phone works after rotating it.** Turning the phone sideways used to make the grid lose track of itself: icons and widgets landed on top of each other wherever you dropped them. The grid is now worked out again for every orientation, an icon dropped on an occupied spot goes to the nearest free one, and nothing overlaps anymore.
  - **Folders finally look like folders.** Out went the colored squares: desktop folders now have a back with a tab, a front cover and the icons of the apps inside peeking out over the edge like papers stuffed in a hurry. They keep whatever color you picked, and the icon you chose for them is now pressed into the front cover in a darker shade of that color. Drag an app over one and the cover swings open to let it in. The File Explorer got the same folders too, with Documents, Photos, Music and friends wearing their own emblem on the cover.

- **2.1.6.164**: Time-bounded the onboarding window, hardening fresh-install setup against late unattended claiming.

The onboarding page exists to create your username and password when none exist yet, that is its entire purpose, so by definition it has to be reachable before any credentials are set, exactly like the first-run setup of almost any self-hosted platform. If you've already completed onboarding, or set your own username and password, none of this affects you, there is no way to run onboarding again once an account exists.     > **TL;DR:** Our Onboarding page has to be open before your account exists, that's its whole job, we just missed putting a clock on it. Now it's a 15-minute window that only a host restart reopens, so a box nobody configured can't be claimed by the wrong person. Turns out "we'll set it up later" needed an expiry date.
